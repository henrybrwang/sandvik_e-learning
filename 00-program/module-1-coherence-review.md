Created: 2026-06-17  
Scope: review of `01-claude-chat/` against `old-assets/Sandvik/AI Fluency Journey.docx` and `old-assets/Sandvik/AI e-learnings.png`  
Module files edited in this pass: none

## Program Context

The Sandvik old-assets material positions Claude Chat as a tool module in the broader AI Fluency Journey, not as a foundation course.

The foundation courses already cover:

- Why AI fluency matters.
- Safe and smart use of approved AI tools.
- Basic prompting habits: context, specificity, and iteration.
- Everyday Copilot Chat use cases.
- The need to verify confident AI output.
- What an agent is, why repeated tasks may deserve an agent, and how first-agent building fits the maturity journey.
- Community, support paths, and how additional tool modules appear as new tools are approved.

The implication for module 1 is that Claude Chat should not try to be the whole AI Fluency foundation again. It should briefly recap essential ideas only where needed, then focus on what is different about Claude Chat and what a user must know before ordering or using it.

## Current Strengths

- The module correctly starts with product fit: Chat is for turn-by-turn thinking, writing, analysis, summarizing, translation, comparison, and reusable outputs.
- The context section is practical and uses a clear vague-prompt to better-prompt example.
- The module includes the important Claude-specific features: files, projects, memory, connectors, skills, artifacts, usage limits, and verification.
- The module separates product capability from Sandvik policy placeholders.
- The quiz tests useful user decisions rather than trivia.

## Coherence Gaps

- The module currently carries too many jobs at once: foundation prompt training, agentic AI explanation, feature catalog, usage/cost guidance, policy reminders, and product routing.
- The middle of the module can feel like a list of features rather than one guided story about how Claude Chat helps a Sandvik user do work.
- "Agentic AI" appears before the context-feature sections, so it may feel abstract before the learner has seen the concrete tools that make the flow possible.
- Usage limits are important but currently interrupt the context/tool story. They may land better as part of "working efficiently and responsibly" near the end.
- The module does not explicitly say how it relates to the existing AI Fluency foundation or Copilot-focused learning, even though the old-assets model says tool modules should cover what is different about the tool.
- The learning objectives are accurate but broad. A shorter set would make the module feel more intentional.

## Recommended Learning Spine

Use one clear thread:

1. Claude Chat is a Claude-specific work partner for thinking, drafting, analyzing, and iterating.
2. It becomes useful when the user gives the right context and boundaries.
3. Claude Chat features are different ways to add, organize, retrieve, reuse, or turn context into outputs.
4. Tool-assisted or agentic chat is a controlled loop: user goal, approved tool access, returned context, Claude output, human review.
5. Sandvik users remain responsible for data choices, verification, sharing, cost, and tool selection.

## Suggested Target Outline

1. **What This Module Adds**
   - State that AI Fluency foundation covers general safe AI use and basic prompting.
   - Explain that this module focuses on Claude Chat specifically: when to use it, what features it includes, and how to use it responsibly at Sandvik.

2. **When Claude Chat Is The Right Tool**
   - Keep the existing Chat/Cowork/Code/Design routing.
   - Add a small adjacent-tool note for Microsoft 365 Copilot and other AI Fluency tools if Sandvik wants users to avoid overlapping tool choices.

3. **The Core Workflow: Context, Boundaries, Output, Review**
   - Keep the current prompt framework, but make it a compact recap.
   - Use one running scenario, such as preparing a steering-group update from approved notes.

4. **Agentic AI In Claude Chat**
   - Explain the tool loop in practical terms: Claude can use approved tools or connectors, bring back context, and continue the conversation.
   - Keep the emphasis on user permissions, approved connectors, and human review.

5. **The Claude Chat Context Stack**
   - Reframe files, projects, memory, connectors, and skills as context mechanisms:
     - Files: context you attach.
     - Projects: context you organize.
     - Memory and chat history: context that may carry forward where enabled.
     - Connectors: context Claude retrieves through approved systems and user permissions.
     - Skills: reusable instructions and resources for repeatable workflows.

6. **Outputs: Artifacts And Sharing**
   - Explain artifacts as outputs to inspect, edit, download, or share.
   - Put sharing and exposure risk here, close to the behavior.

7. **Work Efficiently: Limits, Cost, And Scope**
   - Move usage limits and monthly spending-limit guidance here.
   - Tie cost habits back to focused context, projects, skills, and avoiding unnecessary tool use.

8. **Verification And Sandvik Policy Decisions**
   - Keep verification as the final gate before use.
   - Keep unresolved Sandvik policy items visible, but avoid making placeholders feel like the main learning content.

9. **Practical Examples And Quiz**
   - Use examples that build on the same scenario where possible.
   - Keep the quiz focused on realistic choices: which tool, which context, whether to upload, whether to use a connector, whether to share, what to verify, what to do at a usage limit.

## Concrete Changes To Consider Later

- Add an opening paragraph: "If you have completed the AI Fluency foundation, you have already learned the general rules of safe AI use and basic prompting. This module focuses on what is different about Claude Chat."
- Shorten the learning objectives from ten items to about six grouped outcomes.
- Move usage limits after artifacts and before verification, under a heading such as "Work Efficiently And Manage Usage."
- Rename "How Claude Gets And Uses Context" to something more intentional, such as "The Claude Chat Context Stack."
- Make "Agentic AI" a bridge into connectors and tool access, not a standalone concept lesson.
- Add a simple "Claude Chat versus adjacent tools" decision table if product owners want clearer routing against Microsoft 365 Copilot, GitHub Copilot, Cowork, Code, and Design.
- Thread the examples around one recurring Sandvik scenario rather than unrelated prompt snippets.
- Add a support-path placeholder if the final module should point users to the AI Fluency community, Data & AI SharePoint, Service Portal/IT Service Desk, AI Champions, or Agentic Automation CoE.
- Consider normalizing quiz IDs in a future edit because the current bank skips some numbers. This is not a content blocker if the LMS import accepts the IDs.

## Suggested Module 1 Principle

Module 1 should feel like: "You already know the road rules. Here is how this specific vehicle works, when to choose it, what controls matter, and what you must check before you drive it into real Sandvik work."
